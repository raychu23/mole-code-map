Mole

Everything you need to trust code you didn't write, in the editor you already use — why it's built this way, whether that's still true, and whether an agent's "done" is real. One install. No new tab. No tokens for the checks.

The problem, plainly

Teams write decisions in Slack threads, PR comments and people's heads. Agents write code fast and don't know those decisions exist unless someone pastes them in every time. Nobody re-checks an old decision against the code it governs, so it's wrong in production before anyone notices. Mole keeps a small number of team decisions as plain files next to the code, and checks them for free, every time — no LLM call, no dashboard, no separate tool to remember to run.

What it does, by job

  • Keep the team's decisions enforced — write one in plain language, add a rules: block, every future change is checked for free (mole rules).
  • Know whether an edit touches a past fix — mole check shows past fixes on edited lines, with reasons and guarding tests.
  • See what a function calls, who calls it, what it breaks — the code-map panel (VS Code) / mole map / mole impact, the original mole-code-map feature, kept as-is.
  • Leave notes that survive a rename — mole note add, flagged stale when the code under it changes.
  • MCP tools for any agent — the same decisions/map/check over MCP.

We also say plainly where Mole has not shown a win yet: the first 24 scored runs of an internal agent-task benchmark scored Mole's hooks at 19.5% of available points vs 41.5% with no context — we do not claim a productivity gain anywhere on this site.

Limits

  • TypeScript/TSX only.
  • Rule enforcement checks import/call graphs, not runtime behavior.
  • Tested on macOS (arm64) so far.
  • No productivity claim yet — see above.
  • Local only: no network, no telemetry, no model calls in the core checks.
